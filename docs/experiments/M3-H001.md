# M3-H001 — Pre-registered 7-day momentum signal kill test

**Registration:** 2026-11-09. Experiment ID `M3-H001`.  
**Status:** Research-only; no strategy has trading or account-simulation permission.  
**Historical cutoff (frozen):** `2026-11-09T06:46:19.012Z` / `1794206779012` ms.  
**Research data:** Existing Binance Spot 1h BTCUSDT/ETHUSDT candles, with no future information relative to each daily observation. Up to 365 calendar days before the frozen cutoff.

## Economic hypothesis

Time-series momentum can arise from delayed information diffusion and persistent market participant positioning. This *could* cause a positive trailing 7-day return to predict positive subsequent 24-hour returns. This is an unverified hypothesis, not a conclusion or market forecast.

This first experiment tests **predictive information only**. It does not test an investable portfolio or execution model.

## Frozen daily rule (no parameter sweep)

- At each `00:00 UTC` decision timestamp T, use only BTC and ETH hourly closes from bars completed by T.
- Seven-day score for each asset: `close(T-1h) / close(T-7d-1h) - 1`.
- Choose BTC if its positive score is >= ETH's score.
- Choose ETH if its positive score exceeds BTC's score.
- Choose USDT if **both** scores are <= 0.
- Label the chosen asset with its next 24-hour **close-to-close** outcome: `close(T+23h) / close(T-1h) - 1`; USDT label is zero.
- Use one sample every 24 hours, never intraday overlapping outcomes.
- No indicators, thresholds, stop rules, position sizing, leverage, regime classifiers, agent votes or price optimization are added.

**Important:** labels at T+23h are not executable fills. An actual order after observing the previous hour's final close requires timing, fees, spread and slippage simulation. This diagnostic does **not** model account equity or trades.

## Predeclared comparison and statistical method

All three benchmarks use **exactly the same daily timestamps**:

- USDT: 0% daily nominal USDT return (ignores stablecoin risk).
- BTC: unconditionally observe BTC's next 24-hour close-to-close return.
- ETH: unconditionally observe ETH's next 24-hour close-to-close return.

Outputs: sample count, selection mix, mean/median forward return, fifth/ninety-fifth percentile, positive-day fraction, mean excess versus each benchmark.

Uncertainty: fixed-seed (`20261109`) 1,000-replicate **circular 7-day moving-block bootstrap** of the mean daily excess, with 2.5%/97.5% percentile intervals. These intervals are exploratory and are **not** a claim of simultaneous coverage, independent signals, market-regime robustness, or realized strategy returns.

## Chronological partition and seal

Split available daily observations in chronological order:

1. First 60%: development.
2. Next 20%: validation.
3. Last 20%: **sealed historical test**. Default command does not display test-period returns or signals, only a row count.

No parameter search or reranking after viewing validation. The **historical test is not perfectly blind**, because M2's rolling 180-day aggregate returns and 7-day descriptive indicators were previously observed. A truly prospective evaluation must begin at or after **2026-11-10 00:00 UTC**, in a separate future research milestone.

The `asof`, lookback, daily schedule, outcome horizon, split and statistical seed are frozen in code; do not move them when new bars arrive.

## Go / no-go condition

Only suggest considering a *separately approved* historical-test review if:

- The candidate's **mean daily gross forward excess** versus **USDT**, **BTC**, and **ETH** is strictly positive in **both** development and validation partitions; and
- All three **validation** 95% block-bootstrap lower limits for mean excess are strictly above zero.

Otherwise emit `STOP_NO_SUFFICIENT_EVIDENCE`, archive H001 and **do not tune** thresholds, lookback, asset selection or filters to rescue it. A pass is only a candidate for independent further study; it authorizes **no** simulation account, order ticket or live trade.

## Run once after CI / PR approval

```bash
sudo -u ata /opt/ata/venv/bin/ata research m3-h001 \
  --db /var/lib/ata/market.sqlite3
```

The command uses SQLite `mode=ro` and prints JSON with `development`, `validation`, `reserved_historical_test` and a predeclared decision. It does not write records or send requests to the exchange.

## Failure and stopping criteria

- Missing/gapped data, fewer than 350 days of history or bad prices: fail analysis (do not fill synthetic data).
- No historical validation evidence: archive and stop H001, retain data and experiment record.
- A promising history still requires a forward-looking out-of-sample test and a cost-aware execution model, with separate operational approval, before any account simulation or trading.
